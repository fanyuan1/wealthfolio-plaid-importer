# 0035 — D34: Daily sync

## Context
Wealthfolio must be open to receive data anyway (2026-11-07). Addon storage syncs to paired devices, so a synced switch would run the sync on both, and both would push the same rows (2026-11-09). Two open copies, such as two browser tabs on one server, could both run it (2026-11-09). A change saved mid-run was overwritten by the run's own saves (2026-11-09)

## Decision
A 1-minute timer while Wealthfolio is open runs once a day after the set time (`HH:MM`): dry run, small ratio changes (D29), push. It stops if pushed activities moved (D30), if rows may already be in Wealthfolio (D41), if a security needs review (the same rule that keeps Push off in Sync, computed in the dry run), or if Wealthfolio refused rows; it waits while another task (dry run, push, restore) runs or a change is being saved, and those wait for it: every change the user makes in the addon is refused while it runs, retries 2 hours after a failure, and shows the result as a toast and on the Daily sync step: status (Succeeded, Needs you with a button to the step that fixes it, Failed), next run, counts per account, and the last 7 runs. Run now starts one at once. A run that pushed counts as done for the day. To-do items do not stop it; the run points to Sync, which shows the to-do list of what is left. The manifest declares no `contributes`, so Wealthfolio starts the addon, and the timer, at launch instead of on the first page visit. The on/off switch is an addon secret, which never syncs; the time syncs with the other settings. Every open copy of Wealthfolio that shares the addon storage runs the timer, so a run first takes a lock there: it writes its own id, waits 2 seconds, and runs only if the id is still there. A lock older than 30 minutes is from a copy closed mid-run and is ignored Once a day is known done, the timer skips its storage reads for the rest of that day. Switching the environment clears this, because each environment has its own daily run. Hosted Link and reconnect checks answer "waiting" while the daily sync runs, because finishing them saves connections. The run record is saved inside the task, so a screen that reloads when the task ends shows that run. A run that pushed counts as done even if it then stopped on something, because the next try would push nothing new. The Daily sync step re-reads its state every minute, because another open window may have run the sync. The first timer tick waits one minute, so Wealthfolio can finish starting. The lock has a storage key of its own, so saving the run history never overwrites it.

## Consequences
None recorded beyond the decision.
